# BMTC Data Warehouse & Analytics System

A Snowflake-based data platform and Streamlit application for a public bus transport corporation
modelled on BMTC (Bengaluru Metropolitan Transport Corporation). It is a capstone project: Assignment 1
covers the Snowflake backend and Assignment 2 covers the complete working model.

## Purpose

Bring fleet, depot, workforce, route, trip, ticketing, fuel, maintenance, pass and complaint data into one
governed warehouse. Planners, depot managers and analysts can then answer operational questions such as:
which routes earn the most per km, where delays happen, which buses cost too much to run, and which complaints need attention first.

## Dataset

The dataset is generated by `scripts/generate_data.py` (fixed seed, so the output is identical on every run) and covers
1 Nov 2025 – 31 Oct 2026. Records are internally consistent: buses belong to depots, trips use valid buses, routes and
staff, and each trip's passenger count equals its ticket rows. A small set of data-quality problems is injected on purpose so the
loading pipeline can detect and correct them (see `data/README.md`).

## Architecture

```
CSV / JSON files (data/)
  -> STAGING: file formats, internal stage (PUT), COPY INTO transient STG_* tables, Snowpipe
  -> data-quality checks (temporary table) -> corrected load
  -> BMTC_DW.BUS / TRIP / PASSENGER (permanent tables)
  -> views, materialized view, secure views, JSON/VARIANT analytics
  -> Time Travel, zero-copy clone, Stream -> Task -> summary table
  -> roles, masking & row access policies, data share
  -> Python connector (utils/), Python UDFs, Snowpark stored procedure
  -> Streamlit app (app.py)            -> Power BI (powerbi/)
User -> Streamlit page -> Python logic -> Snowflake -> result -> User
```

**Snowflake objects:** warehouse `BMTC_WH` (XSMALL, auto-suspend 60 s, auto-resume, resource monitor
`BMTC_RM`) · database `BMTC_DW` with these schemas:

| Schema | Contents |
|---|---|
| `BUS` | depots, buses, employees, bus status audit, `BUS_MASTER_CLONE`, `V_BUS_SUMMARY`, secure staff views |
| `TRIP` | routes, trips, tickets, fuel, maintenance, `TRIP_DATA_STREAM`, task, summary table, analytical views, materialized view, Python UDF/procedures |
| `PASSENGER` | passes, `COMPLAINTS_JSON` (VARIANT), complaint/pass views, secure `SV_PASS_HOLDERS` |
| `STAGING` | internal stage, file formats, Snowpipe, transient load tables, rejected rows |
| `GOVERNANCE` | masking policies, row access policy, depot access map |

Roles: `BMTC_VIEWER -> BMTC_ANALYST -> BMTC_MANAGER -> BMTC_ADMIN -> SYSADMIN`.

## Install

```powershell
python -m venv venv                                   # already present in this workspace
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Configure `.env`

Copy `.env.example` to `.env` and fill in your values. `.env` is git-ignored and must never be shared.

```
SNOWFLAKE_ACCOUNT=<orgname>-<accountname>
SNOWFLAKE_USER=<user>
SNOWFLAKE_PASSWORD=<password>
SNOWFLAKE_WAREHOUSE=BMTC_WH
SNOWFLAKE_DATABASE=BMTC_DW
SNOWFLAKE_SCHEMA=BUS
SNOWFLAKE_ROLE=ACCOUNTADMIN
```

Key-pair login is also supported: set `SNOWFLAKE_PRIVATE_KEY` (PEM text) or `SNOWFLAKE_PRIVATE_KEY_FILE`
instead of a password. When deployed, the same keys can be supplied as Streamlit secrets.

## Run locally

```powershell
.\venv\Scripts\python.exe -m streamlit run app.py
```

Then open http://localhost:8501.

Power BI: open `powerbi/BMTC_Dashboard.pbip` in Power BI Desktop (regenerate with `scripts/build_powerbi_project.py`).

Rebuild the Snowflake backend from zero (optional; takes about 4 minutes on an XSMALL warehouse):

```powershell

.\venv\Scripts\python.exe scripts\run_sql.py                         # sql/01 ... sql/12, logs in logs/
.\venv\Scripts\python.exe scripts\run_sql.py powerbi\dashboard_queries.sql
```

## Major features

| Area | Where |
|---|---|
| Dashboard: live KPIs with monthly sparklines, a period switch (3/6/12 months) and 6 charts | app → Dashboard |
| Fleet search/filters, depot & type analysis, **change bus status** (transaction + audit) | Bus Management |
| Route search and detail, top/bottom routes, trip log | Routes & Trips |
| Ticket volume, revenue, payment mix, hourly/weekday and route trends | Ticket Analytics |
| Fuel efficiency (Python UDF), maintenance history, **log a workshop job** | Fuel & Maintenance |
| Passes via secure view, complaint JSON analytics, urgency queue (UDF), **register a complaint** (JSON → VARIANT) | Passengers & Complaints |
| 11 advanced SQL analyses (CTE, windows, correlated subqueries, HAVING) | Advanced Analytics |
| Time Travel, clone, stream/task, Snowpipe, Snowpark procedure, security, warehouse (read-only) | Data Management |
| DDL/DML/DCL/TCL, loading, DQ, JSON, views, Time Travel, clone, stream/task, security, UDF, performance, sharing | `sql/01`–`sql/12` |

All values come from live Snowflake queries. User input is bound as query parameters and never concatenated into SQL.
If Snowflake is unreachable, each page shows one clear message instead of errors or placeholder numbers.

## Power BI

Connect with Power BI Desktop → Get data → Snowflake. Server `<account>.snowflakecomputing.com`, warehouse
`BMTC_WH`, database `BMTC_DW`, role `BMTC_VIEWER`, Import mode. Load the views listed in
`powerbi/POWERBI_SETUP.md`, which also lists the visuals, relationships and DAX measures. The views and queries are
created and tested. The `.pbix` file itself has to be built in Power BI Desktop.

## Known Snowflake trial limitations

- **Data sharing:** the share is created, but no consumer account is available to attach (see `DATA_SHARING.md`).
- **Snowpipe auto-ingest:** this needs an external cloud stage with event notifications. Here, the internal-stage pipe is
  triggered with `ALTER PIPE ... REFRESH`, which was tested.
- **Secondary roles:** the account activates all secondary roles by default. To demonstrate role isolation, run
  `USE SECONDARY ROLES NONE` first.
- **Not enabled, to save credits:** clustering keys (the dataset fits in one micro-partition) and multi-cluster scaling.
  Both are documented in `sql/11_performance.sql`.
